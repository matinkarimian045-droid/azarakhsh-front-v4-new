# Multiplayer Stage 1 - protocol and validation

All event names are case-sensitive. Room/command client events use an acknowledgement
callback with `{ok:true,...}` or `{ok:false,error:"translationKey"}`. The player ID
and reconnect token are generated by the server. Never trust a browser's owner ID.

## Session / room events

| Direction | Event | Payload / purpose |
|---|---|---|
| S -> C | `session:welcome` | `resumeToken`, `playerId`, `roomCode` |
| S -> C | `session:error` | Duplicate active session or rejected state |
| C -> S | `room:create` | `{nation,name}` |
| C -> S | `room:join` | `{code,nation,name}` |
| C -> S | `room:choose` | `{nation}`; unique country, waiting room only |
| C -> S | `room:settings` | Optional `style`, `intel`, `prep`, `startMoney`; host only |
| C -> S | `room:ready` | `{ready:boolean}` |
| C -> S | `room:start` | Empty object; host, exactly two connected ready players |
| C -> S | `room:sync` | Request current room and full viewer snapshot |
| C -> S | `room:leave` | Explicit leave, not a temporary connection loss |
| S -> C | `room:state` | Public players, seats 1/2, host, readiness, rules, pause state |
| S -> C | `match:started` | Full viewer-specific initial/resume snapshot |
| S -> C | `room:closed` | `{reason}` on departure, expiry or handled room fault |

No user password/account is implemented. Session tokens are unguessable bearer
tokens; keep them private. For public deployment, use HTTPS and do not log tokens.
A reconnecting client passes `auth.resumeToken`; one active socket per token is
allowed. A second independent browser profile creates a second player.

The room pauses on a disconnect, retains state for 45 seconds, and resumes with a
full filtered snapshot if that player returns. This is explicit application-level
recovery; we do not assume Socket.IO replays every missed event. A process restart
loses the in-memory session. Explicit leave during a match closes it for both
players; waiting-room departure can transfer host to the remaining player.

## Commands

`game:command` payload:

```json
{"id":1,"type":"launchMissile","args":{"weapon":"ballistic","x":1200,"y":850}}
```

Coordinates above illustrate the protocol only. They must be actual valid target
coordinates in the running match. The server derives the owner from room membership.
Client-supplied hits, damage, health, money, research completions and outcomes are
not valid commands.

Supported command types are defined once in `src/commands.js`:
`build`, `launchMissile`, `produce`, `cancelBuild`, `cancelQueue`, `factoryAuto`,
`research`, `hireScientists`, `sellOil`, `autoSell`, `sellWeapon`, `aircraft`,
`satellite`, `asat`, `operation`, `cancelOperation`, `truce`, `respondTruce`.
Offline-only ally support/order and intel toggles remain behind their guards.
Online room intel is fixed by the host before the start. Human truce offers wait
for the other human to accept/refuse; no AI silently decides for them.

Identifiers are monotonically increasing per session. The last 80 responses are
cached; duplicate requests acknowledge the old result instead of spending resources
or launching twice. Older IDs outside that cache are rejected. The browser retries
a timed-out command once with the same ID. Room changes reset sequence authority.
A token-bucket rate limit and maximum 16 KB incoming packet size bound event spam;
they are not a comprehensive public-internet anti-abuse system.

## Shared simulation and snapshots

`server/load-simulation.cjs` loads trusted source files in one Node VM context.
This is not evaluation of untrusted user code and not a security sandbox. It reuses
the same `Simulation`, `Trajectory`, `GameCommands`, balance tables and land masks
as the offline game. The server runs 30 Hz with bounded catch-up, snapshots 10 Hz.
One simulation is owned by each room; there is no client-authoritative host.

Snapshot filtering removes opponent resources, future defense success flags,
private operations and hidden entities. Detected but unidentified structures use
known-contact representations. Visible enemy missiles have public position and
velocity tracks, not their secret source/target paths. Fog checks happen before
serialization, not just while drawing. Public city locations remain visible by
the game's rule. A filtered event feed avoids disclosing unrevealed construction.

The client reuses read-only simulation helpers for UI and renders up to 120 ms of
visual extrapolation. It does not tick damage, economy, production or AI online.
The match clock is server-owned. Local tactical overlays do not alter online time.

## Test stages

1. `npm test`: shared game, movement and room-service unit tests; FakeIO room transport.
2. `npm run test:syntax`: source, server, tests and compiled JS syntax.
3. `npm run test:network`: **real Express / Socket.IO / socket.io-client** integration.
4. Manual: two independent browser profiles, then two separate computers on one LAN.
5. Only after those pass: deployment/TLS and an outside-LAN test.

Stage 3 was supplied but **not run in the authoring environment** (packages could
not be downloaded). Stage 4/5 are also unverified. Do not describe the room-unit
adapter or injected browser snapshots as real network tests.

## Manual acceptance checklist

Create/join one room with distinct countries. Attempt an early start; it must be
rejected. Ready both and start. Build in each own territory; the other player sees
it only under the configured intelligence rule. Produce ammunition, launch after
preparation and verify matching impacts/resource debits. Try requesting the other
player's entity action; the server must reject it. Disconnect one browser: both
clocks stop. Reconnect within 45 seconds: same country, resources and time return.
Explicitly leave: the opponent is informed. Restart server: rooms are gone by design.
